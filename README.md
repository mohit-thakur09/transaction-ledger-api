# Transaction Ledger API

A backend API for a simple transaction ledger. It supports creating accounts, recording credit and debit transactions, fetching balances and transaction history, and transferring money between accounts.

**Stack:** Node.js, TypeScript, Express 5, SQLite (`better-sqlite3`), Zod for validation.

## Running locally

Requirements: Node.js 20 or newer.

```bash
npm install
npm run dev          # start with auto-reload on http://localhost:3000
```

Production build:

```bash
npm run build
npm start
```

Run the tests:

```bash
npm test
```

### Configuration

| Variable  | Default             | Description                  |
| --------- | ------------------- | ---------------------------- |
| `PORT`    | `3000`              | HTTP port                    |
| `DB_PATH` | `./data/ledger.db`  | SQLite database file path    |

The database file and schema are created automatically on startup. No separate database server is needed.

## Project structure

```
src/
  accounts/        account controller, service, repository, validation schemas
  transactions/    transaction controller, service, repository, validation schemas
  transfers/       transfer controller, service, validation schemas
  db/              connection setup and schema (tables, constraints, triggers)
  errors/          AppError class
  middleware/      404 and error handlers
  utils/           money conversion, shared validation helpers
  routes.ts        wires repositories, services and controllers to routes
  app.ts           Express app factory
  server.ts        entry point
tests/             integration tests (node:test against an in-memory database)
```

Requests flow through **controller → service → repository**. Controllers parse and validate input, services hold the business rules and transaction boundaries, and repositories hold the SQL.

## API documentation

All request and response bodies are JSON. Amounts are decimal numbers with at most 2 decimal places.

### Create account

`POST /accounts`

```json
{ "name": "Alice" }
```

`201 Created`

```json
{
  "id": "dfb124c5-eece-4ae0-bc73-6ff0cc3062c5",
  "name": "Alice",
  "balance": 0,
  "created_at": "2026-10-28T15:29:39.408Z"
}
```

- `name` is required (1–100 characters, trimmed).
- `id`, `balance` and `created_at` are generated by the server. Sending any other field, such as `balance`, returns `400`.

### Add transaction

`POST /accounts/:accountId/transactions`

```json
{
  "type": "credit",
  "amount": 100,
  "reference_id": "salary-2026-10",
  "description": "October salary"
}
```

| Field          | Required | Rules                                       |
| -------------- | -------- | ------------------------------------------- |
| `type`         | yes      | `credit` or `debit`                         |
| `amount`       | yes      | number > 0, at most 2 decimal places        |
| `reference_id` | yes      | non-empty string, max 100 chars, unique per account |
| `description`  | no       | string, max 255 chars                       |

`201 Created`

```json
{
  "id": "6a7d9f00-e4ff-47f6-9793-780d2ac923ea",
  "account_id": "dfb124c5-eece-4ae0-bc73-6ff0cc3062c5",
  "type": "credit",
  "amount": 100,
  "description": "October salary",
  "reference_id": "salary-2026-10",
  "created_at": "2026-10-28T15:29:39.454Z"
}
```

Errors:

- `400 VALIDATION_ERROR`: invalid type, invalid amount, missing `reference_id`, or another invalid field
- `404 NOT_FOUND`: account does not exist
- `409 DUPLICATE_TRANSACTION`: `reference_id` already used on this account. Nothing is created and the balance does not change. The existing transaction is returned in `error.details.transaction`.
- `422 INSUFFICIENT_BALANCE`: the debit amount is more than the current balance. The balance does not change.

### Get account balance

`GET /accounts/:accountId/balance`

`200 OK`

```json
{ "account_id": "dfb124c5-eece-4ae0-bc73-6ff0cc3062c5", "balance": 100 }
```

Errors: `404 NOT_FOUND`

### Get transaction history

`GET /accounts/:accountId/transactions?type=credit&page=1&limit=20`

| Query   | Default | Rules                                   |
| ------- | ------- | --------------------------------------- |
| `type`  | (none)  | `credit` or `debit`. If omitted, both types are returned |
| `page`  | `1`     | integer ≥ 1                             |
| `limit` | `20`    | integer between 1 and 100               |

Transactions are sorted latest first by `created_at`.

`200 OK`

```json
{
  "data": [
    {
      "id": "6a7d9f00-e4ff-47f6-9793-780d2ac923ea",
      "account_id": "dfb124c5-eece-4ae0-bc73-6ff0cc3062c5",
      "type": "credit",
      "amount": 100,
      "description": "October salary",
      "reference_id": "salary-2026-10",
      "created_at": "2026-10-28T15:29:39.454Z"
    }
  ],
  "pagination": { "page": 1, "limit": 20, "total_records": 1, "total_pages": 1 }
}
```

Errors: `400 VALIDATION_ERROR` (invalid `type`, `page` or `limit`), `404 NOT_FOUND`

### Transfer money (bonus)

`POST /transfers`

```json
{
  "from_account_id": "<account A id>",
  "to_account_id": "<account B id>",
  "amount": 30,
  "reference_id": "transfer-001",
  "description": "Rent share"
}
```

`201 Created`

```json
{
  "debit_transaction":  { "id": "...", "account_id": "<A>", "type": "debit",  "amount": 30, "reference_id": "transfer-001", "...": "..." },
  "credit_transaction": { "id": "...", "account_id": "<B>", "type": "credit", "amount": 30, "reference_id": "transfer-001", "...": "..." }
}
```

A transfer records a debit on the source account and a credit on the destination account inside one database transaction. If any step fails, the whole transfer is rolled back.

Errors: `400 VALIDATION_ERROR` (including source and destination being the same account), `404 NOT_FOUND`, `409 DUPLICATE_TRANSACTION`, `422 INSUFFICIENT_BALANCE`

### Error format

All errors use the same format:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid request data",
    "details": [{ "field": "amount", "message": "amount must be greater than 0" }]
  }
}
```

| Status | Code                    | When                                      |
| ------ | ----------------------- | ----------------------------------------- |
| 400    | `VALIDATION_ERROR`      | Invalid body, query parameters or values  |
| 400    | `INVALID_REQUEST_BODY`  | Malformed JSON                            |
| 404    | `NOT_FOUND`             | Account does not exist                    |
| 404    | `ROUTE_NOT_FOUND`       | Unknown route or method                   |
| 409    | `DUPLICATE_TRANSACTION` | `reference_id` already used on the account |
| 422    | `INSUFFICIENT_BALANCE`  | Debit or transfer exceeds the balance     |
| 500    | `INTERNAL_ERROR`        | Unexpected server error                   |

## Data integrity

- **Atomicity:** inserting a transaction and updating the account balance run inside one SQLite transaction. A transfer wraps both legs in an outer transaction, so neither leg is committed unless both succeed.
- **Consistency:** `better-sqlite3` runs transactions synchronously, so concurrent requests cannot interleave between reading the balance and writing it.
- **Database constraints:**
  - `CHECK (balance >= 0)` on accounts
  - `CHECK (amount > 0)` and `CHECK (type IN ('credit','debit'))` on transactions
  - `UNIQUE (account_id, reference_id)`
  - a foreign key from `transactions.account_id` to `accounts.id`
- **Immutability:** the API has no update or delete endpoints for transactions. DB triggers also reject any `UPDATE` or `DELETE` on the `transactions` table.

## Assumptions

1. **Money representation:** amounts are accepted and returned as decimal numbers with up to 2 decimal places. They are stored as integers in minor units (cents) to avoid floating-point errors. The maximum amount for one transaction is 1,000,000,000.
2. **Single currency:** the ledger does not handle currencies.
3. **Duplicate response:** a repeated `reference_id` on the same account returns `409 Conflict` with the original transaction. The duplicate check runs before the balance check, so a repeated debit always reports a duplicate.
4. **Insufficient balance** returns `422 Unprocessable Entity`, because the request is valid but violates a business rule.
5. **Unknown fields** in request bodies are rejected with `400`. This is how the API stops clients from setting the initial balance.
6. **Account IDs** are UUIDs generated by the server. Any ID that does not match an existing account, including a malformed one, returns `404`.
7. **Description** is optional.
8. **Transfers** require a `reference_id`, which is used on both the debit and the credit transaction. It must therefore be unused on both accounts, otherwise the transfer is rejected with `409` and nothing is changed. If no description is given, a default one ("Transfer to/from <account id>") is stored.
9. **Pagination:** a page beyond the last one returns an empty `data` array, not an error. `limit` is capped at 100.
10. **Sorting:** transactions with the same `created_at` timestamp are ordered by insertion order, newest first.
11. **Authentication** is out of scope, as the assessment does not require it.
